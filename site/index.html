Thousands of Postgres clients. A few server connections.

pgmux is a connection pooler for Postgres 14 to 17. It speaks the wire protocol, so your apps and drivers need no changes.

What pgmux does

Transaction pooling, with prepared statements

A client holds a server connection only while its transaction runs. When the transaction ends, the next client gets that connection.

  • Prepared statements work. pgmux prepares each statement again on the server that the client lands on. Clients need no flags.
  • Client settings stay with their client. A SET TimeZone from one client never reaches a different client.
  • Session mode is there too. Choose the mode for each database.
pgmux.yaml
pool_mode: transaction

pool:
  default_size: 20
  query_wait_timeout: 30s

databases:
  appdb:
    pool_size: 50
  reports:
    dbname: appdb
    pool_mode: session
    pool_size: 5

Authentication and TLS

pgmux logs clients in itself, and then connects to Postgres for them.

  • SCRAM-SHA-256 and MD5. Use a PgBouncer-style userlist file.
  • No passwords on disk. With auth_query, pgmux gets the password hash from Postgres.
  • TLS on both sides. Accept TLS from clients, and connect to Postgres with verify-full.
pgmux.yaml
server:
  host: db.internal
  sslmode: verify-full

client_tls:
  cert_file: server.crt
  key_file: server.key

auth:
  method: scram-sha-256
  auth_user: pgmux
  auth_query: SELECT usename, passwd
    FROM pg_shadow WHERE usename = $1

See the pools while they work

Watch clients, server connections and wait times live during a load test.

  • Prometheus metrics for clients, servers, wait times and errors. A Grafana dashboard is included.
  • A live dashboard served by the admin API.
  • An admin API to pause, resume and reload pools.

Change the config without a restart

pgmux reloads the config file and the userlist when they change. Pool sizes, timeouts, users and certificates update in place.

  • Pause a pool for a database restart. New queries wait until you resume, up to query_wait_timeout.
  • Graceful shutdown. On SIGTERM, open transactions get time to finish.
shell
# Stop handing out server connections
curl -X POST "localhost:9930/pause?db=appdb"

# Restart Postgres, then continue
curl -X POST "localhost:9930/resume?db=appdb"

# Load the config again
curl -X POST localhost:9930/reload

Benchmarks

pgbench against PgBouncer 1.24, both in transaction mode with 25 server connections. With prepared statements and 100 or more clients, pgmux is 20% to 45% faster. With the simple protocol, PgBouncer is faster.
